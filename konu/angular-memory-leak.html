Angular Memory Leak(Bellek Sızıntıları) Tespiti ve Önleme Yöntemleri

Angular Bellek Sızıntıları

Angular'da bellek sızıntıları, kaynakların düzgün bir şekilde serbest bırakılmaması nedeniyle zamanla gereksiz bellek tüketimine yol açabilir. Bu sızıntılar, uygulamanın yavaşlamasına veya sonunda çökmesine neden olabilir. Aşağıda, Angular uygulamalarında bellek sızıntılarına neden olabilecek yaygın sebepler ve çözüm yolları yer almaktadır:

1. Aboneliklerin Kapatılmaması

Angular'da bellek sızıntılarının en yaygın sebeplerinden biri, Observable veya EventEmitter'lara olan aboneliklerin kapatılmamasıdır.

Çözüm:

takeUntil operatörü veya Angular'ın ngOnDestroy yaşam döngüsü kancası ile Observable aboneliklerini kapatmak gerekir. İşte bir örnek:

import { Component, OnDestroy } from '@angular/core';
import { Subject } from 'rxjs';
import { MyService } from './my-service';

@Component({
	selector: 'app-my-component',
	templateUrl: './my-component.component.html',
})
export class MyComponent implements OnDestroy {
	private destroy$ = new Subject();
	
	constructor(private myService: MyService) {}
	
	ngOnInit() {
		this.myService.getData()
		.pipe(takeUntil(this.destroy$))
		.subscribe(data => {
			// veriyi işleme
		});
	}
	
	ngOnDestroy() {
		this.destroy$.next();
		this.destroy$.complete();
	}
}

takeUntil kullanmak, bileşen yok edildiğinde aboneliğin otomatik olarak kapatılmasını sağlar.

2. Olay Dinleyicilerinin Kaldırılmaması

Eğer özel olay dinleyicileri (örneğin window veya document dinleyicileri) eklerseniz ve bileşen yok edildiğinde bunları kaldırmazsanız, bellek sızıntılarına yol açabilir.

Çözüm:

Olay dinleyicilerini ngOnDestroy yaşam döngüsü kancasına kaldırmalısınız.

@Component({
	selector: 'app-my-component',
	templateUrl: './my-component.component.html',
})

export class MyComponent implements OnDestroy {
	ngOnInit() {
		window.addEventListener('resize', this.onResize);
	}

	ngOnDestroy() {
		window.removeEventListener('resize', this.onResize);
	}

	private onResize(event: Event) {
		console.log('Pencere boyutu değişti', event);
	}
}

3. Yönetilmeyen Referanslar

Kullanılmayan ancak bellekte tutulan nesneler veya hizmetler bellek sızıntılarına neden olabilir. Örneğin, bir bileşen hizmetlere veya büyük veri nesnelerine referans tutmaya devam ederse, bu nesneler çöp toplama (garbage collection) tarafından serbest bırakılmaz.

Çözüm:

Kullanılmayan nesneleri null veya undefined yaparak bellekten temizlenmelerini sağlayabilirsiniz.

ngOnDestroy() {
	this.myService = null;  // Hizmetin referansını temizler
}

4. Değişim Algılamanın Ayrılması (Detached Change Detection)

Bazen, Angular'ın değişim algılama mekanizması bellek sorunlarına yol açabilir, özellikle değişim algılamasını manuel olarak ayırdığınızda.

Çözüm:

ChangeDetectorRef'i dikkatli kullanın. Değişim algılamasını yalnızca gerekli olduğunda ayırın ve gerektiğinde tekrar bağlayın.

constructor(private cdRef: ChangeDetectorRef) {}

ngOnInit() {
	this.cdRef.detach(); // Performans için algılamayı ayır
}

ngOnDestroy() {
	this.cdRef.reattach(); // Gerekirse yeniden bağla
}

5. Lazy Loading Sorunları

Lazy-loaded (tembel yüklenen) modüllerle büyük Angular uygulamalarında, modüllerin düzgün bir şekilde temizlenmemesi bellek sızıntılarına yol açabilir.

Çözüm:

Lazy-loaded modüllerin doğru şekilde yapılandırıldığından ve modülün temizlendiğinden emin olun.

// Lazy Loaded Modül Örneği
const routes: Routes = [
	{
		path: 'lazy',
		loadChildren: () => import('./lazy/lazy.module').then(m => m.LazyModule),
	},
];

6. Üçüncü Taraf Kütüphaneleri

Bazı üçüncü taraf kütüphaneleri, kaynakları düzgün şekilde temizlemeyebilir ve bu da bellek sızıntılarına neden olabilir.

Çözüm:

Üçüncü taraf kütüphanelerinin Angular ile uyumlu olduğundan ve kaynakları etkin bir şekilde yönettiklerinden emin olun. Belirli bir kütüphanenin dökümantasyonunu kontrol ederek, kaynakların nasıl temizleneceğiyle ilgili bilgi edinin.

7. NgFor'da Değişim Takibi

ngFor ile büyük liste öğeleri kullanırken, değişikliklerin düzgün bir şekilde takip edilmemesi, Angular'ın görünümden kaldırılan öğelere olan referansları bellekte tutmasına yol açabilir.

Çözüm:

Listelerdeki değişikliklerin nasıl işlendiğini optimize etmek için trackBy fonksiyonunu kullanın.

<div *ngFor="let item of items; trackBy: trackById">
	{{ item.name }}
</div>

trackById(index: number, item: any): number {
	return item.id;
}

8. Global State ve Singletonlar

Angular hizmetleri genellikle singleton nesnelerdir ve büyük veri kümelerini veya diğer nesneleri global durumda saklamak, düzgün temizlenmediklerinde bellek sızıntılarına yol açabilir.

Çözüm:

Büyük ve gereksiz verileri globalde saklamaktan kaçının. Eğer ihtiyaç varsa, Angular’ın Injector'ını veya uygun desenleri kullanarak yaşam döngüsü yönetimini sağladığınızdan emin olun.

Bu uygulamaları takip ederek bellek sızıntılarını en aza indirebilir ve Angular uygulamanızın performansını ve kararlılığını artırabilirsiniz. Chrome'un Geliştirici Araçları gibi araçları kullanarak bellek kullanımını düzenli olarak profil çıkarabilir ve potansiyel sızıntıları tespit edebilirsiniz.
